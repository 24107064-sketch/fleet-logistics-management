# PROJECT: FLEET & LOGISTICS MANAGEMENT SYSTEM
## Static Website UI — Complete Product and Design Specification

Act as a senior UI/UX designer, frontend architect, and product designer. Design and implement a complete, polished, production-quality static website for a Fleet and Logistics Management System.

The website will be the frontend foundation for a college DevOps mini project. The application will eventually integrate with a Node.js and Express backend, an SQLite database, Docker, and a GitHub Actions CI/CD pipeline. However, **the current phase must be a static, frontend-only website**.

Do not build the backend, database, authentication server, API, or deployment pipeline in this phase. Use realistic mock data and client-side interactions so the website feels functional without requiring a server.

---

# 1. PRODUCT VISION

Product name: Fleet & Logistics

Product category: Fleet management, shipment tracking, transportation operations, and logistics administration.

Purpose:
Create a unified operations dashboard that helps logistics administrators monitor vehicles, manage drivers, organize shipments, track delivery progress, and review fleet performance from a single interface.

Target users:
- Fleet managers
- Logistics administrators
- Transport coordinators
- Dispatch operators
- Operations supervisors

The interface should feel like a serious operational tool used by a modern logistics company, not a generic admin template.

Primary objectives:
1. Monitor fleet availability and utilization.
2. Maintain vehicle and driver records.
3. Create, assign, and track shipments.
4. Monitor deliveries and shipment exceptions.
5. Display operational KPIs and performance trends.
6. Make common administrative tasks easy to complete.
7. Establish a clean frontend architecture that can later connect to REST APIs.

# 2. VISUAL DESIGN DIRECTION

Create a distinctive visual identity combining industrial operations software, editorial print design, and technical data terminals.

The design must feel:
- Minimal
- Editorial
- Technical
- Precise
- Functional
- Calm
- Professional
- Data-oriented

Avoid:
- Generic SaaS dashboard templates
- Excessive gradients
- Glassmorphism
- Large rounded cards everywhere
- Excessive shadows
- Oversized colorful icons
- Cartoon illustrations
- Unnecessary animations
- Excessive whitespace that hides useful information
- Default Bootstrap styling
- A conventional blue-and-purple AI dashboard aesthetic

Use a strong typographic hierarchy, thin separators, precise alignment, compact tables, and deliberate spacing.

## 2.2 Typography — critical requirement

Typography is a central part of the design. Use IBM Plex Mono and Georgia as the primary typefaces.

Primary typeface:
IBM Plex Mono

Use IBM Plex Mono for:

- Buttons
- Table headers
- Table values

- Shipment IDs
- Status badges
- KPI labels
- Timestamps
- Search fields
- Form labels
- Breadcrumbs

Secondary typeface:
Georgia, with a traditional serif fallback.

Use Georgia for:
- Main page headings
- Dashboard title
- Large KPI numbers when appropriate
- Section introductions
- Empty-state headlines
- Modal titles
- Editorial callouts
- Important explanatory text

For supporting prose, use Georgia or a readable sans-serif such as Inter.

Suggested CSS font stacks:

IBM Plex Mono:
"IBM Plex Mono", "Courier New", monospace

Georgia:
Georgia, "Times New Roman", serif

Supporting sans-serif:
Inter, Arial, sans-serif

Import IBM Plex Mono and Inter from Google Fonts when internet access is available. Georgia should use the system font rather than requiring a downloaded web font.

Provide sensible fallbacks so the website still renders when external fonts are unavailable.

Use these typography conventions:
- Page titles: Georgia, 36–44px desktop, 30–34px mobile.
- Section titles: Georgia, 23–28px.
- KPI values: Georgia, 32–44px or IBM Plex Mono for technical counters.
- Body text: 14–16px.
- Table content: IBM Plex Mono, 12–14px.
- Navigation: IBM Plex Mono, 12–13px.
- Eyebrow labels: IBM Plex Mono, 10–11px, uppercase, letter spacing 0.08em.
- Buttons: IBM Plex Mono, 12–13px.

Use font weights deliberately. Prefer regular and medium weights over excessive bold text.

## 2.3 Layout

Desktop:
- Fixed or sticky left sidebar, approximately 240px wide.
- Main workspace fills the remaining width.
- Top header around 68px high.
- Main content max-width approximately 1600px.
- Page padding 28–36px.
- Consistent 8px spacing scale.
- Use CSS Grid for dashboards and responsive layouts.
- Tables should have strong column alignment and clear row separators.

Mobile:
- Replace the fixed sidebar with a slide-out navigation drawer or compact menu.
- Stack KPI cards.
- Make tables horizontally scrollable or provide a responsive list alternative.
- Keep primary actions accessible.
- Avoid clipped text and horizontal page overflow.

Use thin 1px borders and mostly square or subtly rounded corners, generally 2–6px. Avoid pill-shaped containers except for status indicators.
